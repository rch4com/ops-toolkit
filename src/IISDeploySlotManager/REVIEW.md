# REVIEW.md — IISDeploySlotManager

## 현재 상태

2026-11-13: 인터뷰 기반 설계 초안 6종 작성. 실행 코드·프로젝트·설치·서버 변경은 수행하지 않았다. 사용자 검토 전 구현 완료로 취급하지 않는다.

추가 요구 반영: 암호화 압축 패치 업로드·관리자 암호 검증·DB 암호문 보관·예약/재배포 재사용, Windows NLB 또는 기존 로드밸런서 기반 Active–Active 2노드 페어로 범위를 확장했다. 단독 서버 설계는 유지하되 HA 조정·분산 상태가 추가되었다.

현재 개정: 사용자 지정에 따라 별도 공통 DB 설계를 폐기하고 노드별 SQLite·패키지 보관소와 전용 동기화 프로토콜로 변경했다. 특권 작업은 Windows 서비스로 한정하고 IPC 우선/인증된 로컬 HTTP 대체 계약을 추가했다. 트래픽 Active–Active와 지정 단일 배포 조정 역할을 구분하며 통신 분할 시 신규 페어 변경을 보류한다.

이번 보완: 문서 리뷰 6항목을 SPEC에 반영하고 롤백 원본을 배포 전 백업 압축파일로 명시했다. 웹/서비스/SQLite 장애의 로컬 수동 복구와 강제 논리 동기화를 추가했다. 한쪽 업로드의 상대 자동 복제 및 최초 페어링부터 등록 노드만 허용하는 mTLS 인가 계약을 강화했다. 필수 6문서 외에 RECOVERY.md를 추가했으며 모두 미구현 설계다.

설명 문서 추가: BACKGROUND.md에 제작 배경·취지·대상 사용자·성공 판단/한계를, ARCHITECTURE.md에 전체 구성/업로드 도표와 권한·동기화·복구 경계·설계 선택 이유를 정리했다. README에 읽기 순서를 연결했다. 총 9개 문서이며 별도 독립 리뷰와 실제 동작 검증은 아직 하지 않았다.

## 미확정 환경 정보

실제 DNS·인증서·AD 그룹/Entra 앱 등록·계정, 암호화 도구·키 보관, 업무별 점검과 알림 채널, 보존 기간·중지 기한은 설치 환경별로 확정한다. DB 제품은 내장 SQLite로 확정했으며 provider·backup/스키마 상세, 압축 지원표/라이브러리, 동기화 protocol/인증/제한, 패키지 복제, NLB/LB 연동 범위는 구현 전 검토 대상이다. 이 문서의 체크는 자동/실환경 시험 통과를 의미하지 않는다.

## 제한

강제 종료는 진행 중 요청을 잃을 수 있다. 단독 구성의 서버 장애, 기존 NLB/LB 자체의 HA, 업무 DB/업로드 데이터 자동 복구·호스팅 전환 무손실은 보장하지 않는다. 관리 SQLite/패키지의 동기화는 시점 백업을 대체하지 않는다. 페어 전환 중 혼합 버전이 발생할 수 있고 통신 단절 중 신규 페어 배포는 보류한다. 두 노드만으로 자동 조정 failover를 제공하지 않는다. 모듈 실행은 샌드박스가 아니다. 암호화만으로 서버 관리자나 서비스 계정 침해를 방어할 수 없다. 패키지 암호 보호 키를 잃으면 과거 패키지 재배포가 불가능해질 수 있다.
