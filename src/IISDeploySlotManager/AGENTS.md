# AGENTS.md — IISDeploySlotManager

루트 [AGENTS.md](../../AGENTS.md)를 따른다. 작업 전 로컬 INTENT.md → SPEC.md → PLAN.md → REVIEW.md 순서로 읽는다.

## 현재 상태

문서 초안만 존재한다. 사용자 문서 검토 전 코드·프로젝트·설치 작업을 시작하지 않는다. 신규 도구 문서 6종을 유지한다.

## 구현 기준

- .NET 10. 웹/프록시와 UI 비종속 코어·Windows 제어를 분리한다. 기존 OpsToolkit.Shared는 계약이 맞는 부분만 재사용하며 BCL-only 조건을 바꾸지 않는다.
- 운영 앱·App Pool은 솔루션의 전용 리소스여야 한다. 임의 PID/전체 w3wp/공용 풀/IIS 전체 재시작으로 문제를 해결하지 않는다.
- UI 권한 검사만 신뢰하지 않는다. Controller가 호출자·명령·경로·리소스 범위를 다시 검사한다.
- IIS/프로세스 조회·정상/강제 종료·배포·암호화·예약·동기화는 Windows 서비스가 수행한다. 필요한 권한은 설치 단계에서 위임하며 웹·Proxy를 관리자/LocalSystem으로 올리지 않는다.
- IPC와 로컬 HTTP API는 같은 명령 계약·RequestId·권한 검사를 사용한다. 인증/권한 실패를 HTTP 우회로 해결하지 않는다. 연결 불가 fallback 후 중복 실행을 방지하고 결과 불명은 상태 조회로 대조한다.
- 권한 부족을 숨기거나 자동 승격하지 않는다. NeedsAdministrator 상태와 이력·알림을 남긴다.
- 작업·잠금·예약은 브라우저와 웹 App Pool 수명에 의존하지 않는다. 중복 실행·재부팅·부분 실패를 검증한다.
- 비밀값·실제 서버 정보·인증서 개인 키를 코드·문서·감사 로그에 넣지 않는다.
- 패키지 암호는 재사용 가능한 암호문으로만 DB에 저장한다. 암호화 키는 DB 밖에서 보호하고 로그·프로세스 명령줄·모듈 출력으로 암호가 나오지 않게 한다. 패키지 암호화와 배포 후 설정 암호화를 분리한다.
- DB는 노드별 SQLite로 확정했다. 별도 DB 서버·공통 DB 잠금·SMB DB 공유·실행 중 DB/WAL 파일 복제를 도입하지 않는다. 로컬 DB 쓰기는 Controller로 단일화하고 트랜잭션 outbox/inbox로 변경을 전송·중복 제거한다.
- HA는 기존 NLB/LB 뒤의 Active–Active 2노드 페어다. 배포 조정 노드 하나가 명령 순서를 확정하고 상대의 영속 ACK를 확인한다. 관측 정보의 원본 노드와 변경 명령의 권위를 구분한다. timestamp 기반 last-write-wins를 사용하지 않는다.
- 조정 세대·작업·단계별 실행 허가·멤버십 revision을 검사하고 미동기화 변경으로 실행하지 않는다. 통신 단절만으로 조정 권한을 자동 승격하지 않는다. 인계는 양쪽 합의 또는 기존 조정 노드의 실행 차단 확인을 요구한다.
- 노드별 검증·부분 실패·혼합 버전을 명시한다. 임의 NLB 전체 drain/stop 또는 다른 솔루션의 트래픽 제외를 수행하지 않는다.
- 등록된 모듈만 실행한다. 명령 문자열을 셸에 연결하지 않는다. 모듈은 샌드박스가 아니며 최소 권한이 별도로 필요하다.
- JSON/XML 변환·암호화·정상 롤백은 비운영 슬롯에 적용한다. 긴급 활성 사이트 복원은 15절의 트래픽 차단·중지·RecoveryHold를 충족하는 명시적 복구 작업으로만 허용한다. 일반 배포/동기화 우회로 제공하지 않는다.
- 롤백 원본은 검증된 백업 압축파일이다. 라우팅만 복귀하면 임시 트래픽 복귀로 기록한다. CurrentServingRecovery와 TargetBeforeOverwrite를 구분하고 전체 검증·키 접근 전 파일 변경을 시작하지 않는다. manifest로 새 관리 파일의 잔여물도 정리한다.
- Proxy AppliedRevision/InstanceId와 실제 경유 릴리스를 확인하기 전 이전 슬롯을 중지·덮어쓰지 않는다. 마지막 적용 라우팅은 Controller/SQLite와 독립 복구 가능해야 한다.
- 정상 페어 ACK와 장애 인계의 복구 전용 멤버십을 구분한다. 구노드의 실행 차단 없이 새 세대를 만들지 않는다. offline 복구는 서비스 자동 재시작 차단·공유 복구 잠금·독립 저널·재기동 Hold를 요구한다.
- 강제 동기화는 기준 소스/대상/scope의 공유 논리 데이터만 백업·diff·트랜잭션으로 복구한다. 노드 ID/개인 키/PID/실제 라우팅/감사를 덮어쓰거나 과거 예약·실행 허가를 replay하지 않는다.
- 한쪽 업로드를 상대에도 자동 전송하고 LocalVerified와 PairReady를 구분한다. 모든 원격 채널은 mTLS·명시적 PairId/NodeId/등록 키 인가를 요구한다. 같은 CA 인증서나 IP만으로 허용하지 않는다.
- 최초 페어링도 양쪽의 인증된 관리자 경로와 out-of-band 공개 지문 검증으로 신뢰를 등록한다. 무인증 원격 bootstrap API·인증서 검증 우회·개인 키 동기화를 만들지 않는다. 키 교체/폐기는 활성 세션·작업 허가에도 반영한다.
- 로컬 스크립트를 추가하면 PowerShell 7 도움말·StrictMode·ShouldProcess·구조화 출력 계약을 지킨다.

## 구현 후 사용할 검증 명령

현재 프로젝트/솔루션/테스트는 없다. 구현 시 도구 폴더에 IISDeploySlotManager.sln을 두고 대응 테스트를 포함하며, 루트 OpsToolkit.slnx에도 등록한다.

```powershell
dotnet build -warnaserror
dotnet format --verify-no-changes
dotnet test --nologo
```

상태 변경 CLI는 `--dry-run`으로 시스템 변경·프로세스 종료·모듈 실행 없이 계획만 출력한다. 실제 IIS/서비스/인증서 검증은 격리된 테스트 리소스에서 수행하고 결과를 REVIEW.md에 기록한다.

긴급 복구 유지보수 시 [RECOVERY.md](RECOVERY.md)를 함께 읽는다. 실행기/명령은 아직 없으며 운영 절차 설명을 현재 실행 가능한 명령으로 오해하게 만들지 않는다.
