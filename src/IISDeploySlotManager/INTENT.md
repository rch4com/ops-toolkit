# INTENT.md — IISDeploySlotManager

## 해결하려는 문제

현재 IIS 중지 후 배포로 서비스 공백이 발생한다. 운영자가 수작업으로 두 사이트·설정·인증서·점검·전환을 관리하면 오배포, 설정 소실, 복구 실패와 변경 이력 누락이 발생하기 쉽다.

배경·취지와 대상 사용자 설명은 [BACKGROUND.md](BACKGROUND.md), 구성 요소·권한·흐름·선택 이유는 [ARCHITECTURE.md](ARCHITECTURE.md)에 정리한다. 확정 요구와 상세 계약은 이 문서 및 SPEC.md가 기준이다.

## 인터뷰로 확정된 요구

- 한 서버에서 YARP와 IIS Blue/Green을 운영하고 ARR/L4 없이 전환한다.
- 단독 구성을 확장해 Windows NLB 또는 기존 로드밸런서 기반 Active–Active 서버 2대를 페어로 등록하고 노드별 Blue/Green 배포·점검·전환·예약을 조정한다.
- 암호화 압축 패치 패키지를 업로드하고 관리자 페이지에서 암호 확인 후 진행한다. 재배포·예약/복구에 필요한 패키지 암호는 DB에 암호문으로 보관한다.
- DB 서버를 별도 설치하지 않는다. 각 노드의 내장 SQLite에 정보를 저장하고 전용 서비스 간 프로토콜로 설정·작업·암호문·배포 패키지를 동기화한다.
- 특권 작업은 Windows 서비스에서 실행한다. 웹↔서비스는 IPC 우선, 연결 불가 시 인증된 로컬 HTTP 계열 통신으로 대체한다.
- YARP는 IIS 호스팅과 Windows 서비스 실행을 모두 지원한다.
- 관리자 웹에서 기본 정보를 받아 사이트·풀을 구성하고 운영 기능을 제공한다.
- 관리 웹만 Windows 또는 Entra ID 인증을 사용한다. 특별관리 계정을 구분한다.
- Blue/Green 각각의 검증 주소와 자동·수동 핵심 기능 점검을 제공한다.
- 점검은 솔루션별로 등록 가능한 스크립트·모듈로 확장한다.
- 롤백 원본은 배포 전 생성한 백업 압축파일이다. 현재 운영 릴리스 복구 백업과 덮어쓸 대상의 변경 전 백업을 구분하고 검증 실패 시 배포를 차단한다. 특정 버전 원본 패키지 재배포는 별도 작업이다.
- 긴급 시 백업 압축파일로 중지한 사이트를 직접 덮어쓰는 수동 복원을 제공한다. 웹/Controller/관리 SQLite가 불가한 경우도 로컬 OS 관리자·복구 실행기·독립 백업/키·복구 잠금으로 복원할 수 있게 한다.
- SQLite 논리 데이터 불일치는 기준 서버와 대상/범위를 지정한 강제 동기화로 복구한다. 양쪽 사전 백업·diff·검증을 요구하며 노드 전용 정보/감사/작업 실행 권한을 일괄 덮어쓰지 않는다.
- 한쪽 업로드는 상대 서버로 암호화 원본 파일을 자동 전송한다. 양쪽 영속 보관·파일/암호 검증 후에만 페어 배포 준비 완료다.
- 서버 간 데이터·배포/백업 파일은 mTLS HTTPS 전용 메시지 규약으로 통합 동기화한다. 양쪽 관리자 신뢰 등록과 등록 노드 인가를 요구하고 무인증 통신·키/암호 평문 전송·인증 우회를 금지한다.
- JSON(appsettings.json), XML(web.config 및 별도 XML)의 버전별 차이·변환·보호를 관리하며 배포 후 암호화가 필요한 경우를 지원한다.
- 사이트·풀 중지를 확인하고 제한 시간 후 권한과 대상 소유권이 확인되면 강제 종료한다. 권한 부족 시 관리자에게 중지 요청을 알린다.
- 지정 날짜/시각 이후 미갱신 대기 슬롯을 자동 배포하는 옵션을 제공한다.
- 운영·보안·이력·장애 복구를 설계에 포함한다.

## 성공 기준

정상 배포뿐 아니라 검사 실패, 권한 부족, 중지 지연, 외부 설정 변경, 재부팅·서비스 중단에서도 현재 운영 대상을 임의로 중지·덮어쓰지 않는다. 검증된 앱·설정·프로필 조합만 전환하고, 작업자와 단계별 결과를 추적할 수 있어야 한다.

## 비목표와 제약

- NLB/LB 자체의 구축·일반 장애조치 엔진, DB/업로드 데이터 자동 롤백, Azure의 모든 슬롯 기능 복제는 하지 않는다. 페어 배포 제어와 기존 트래픽 HA를 구분한다.
- IIS/서비스 호스팅 전환에 무손실·무중단을 약속하지 않는다.
- 설정 의미·암호화 형식을 추측해 자동 변환하지 않는다. 호환되지 않거나 규칙이 없으면 차단한다.
- 관리 웹에 임의 명령 실행·공통 비밀번호·숨겨진 인증 우회를 제공하지 않는다.
- 사이트/풀을 강제 종료할 수 있어도 공용 풀이나 소유 관계가 불명확한 프로세스는 종료하지 않는다.
- 자동 배포는 대상 버전을 명시한 대기 슬롯 갱신이며 자동 운영 전환을 포함하지 않는다.
- 페어 노드의 전환을 동시에 완료하는 분산 원자성을 보장하지 않는다. SQLite와 비동기 동기화만으로 통신 분할 중 양쪽의 독립 배포를 허용하지 않는다. 동기화·패키지·키 준비가 불확실하면 신규 페어 변경을 보류하고 기존 서비스는 유지한다.
- HA 트래픽은 Active–Active이지만 배포 조정은 지정된 단일 조정 노드가 맡는다. 별도 witness 없이 두 노드가 서로 단절된 상황에서 자동 조정 노드 승격을 제공하지 않는다.
- 장애 인계는 구노드의 실제 실행 차단 후 복구 전용 DegradedMaintenance로 수행하며 양쪽 확인이 필요한 정상 페어 작업과 구분한다. 방화벽 차단만으로 구노드가 멈췄다고 판단하지 않는다.
- 앱 롤백은 관리 SQLite의 과거 시점 복원이 아니다. 업무 DB/사용자 데이터·외부 부작용을 백업 압축파일로 되돌릴 수 있다고 주장하지 않는다.

## 설치 시 구체화할 항목

대상 서버/런타임, 도메인·DNS·인증서, 특별관리 계정의 실제 용도·역할, AD 그룹/Entra 앱 등록, 암호화·변환 모듈, 점검 스크립트, 알림 수신·전송 방식, 보존 기간과 제한 시간은 배포 환경별 값으로 받는다. 페어에서는 NLB/LB 상태 확인·제외 연동, 조정 노드, 동기화 endpoint/인증서, 로컬 DB/패키지 보관 경로와 키 보호/복구도 지정한다. 압축 형식·암호화 알고리즘은 지원표 확정 전 선택 사항이다. 예시 운영 계정이나 비밀정보를 저장소에 고정하지 않는다.
